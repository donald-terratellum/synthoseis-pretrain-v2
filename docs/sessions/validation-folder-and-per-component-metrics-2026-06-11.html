Session Summary: Validation Folder and Per-Component Metrics

Date: 2026-06-11  |  Branch: feature/multi-loss-and-unet-levels  |  training metrics validation LPIPS

Context and Goals

The seismic pre-training codebase (synthoseis-pretrain-v2) runs a 3D UNet that reconstructs seismic volumes from synthoseis-generated Zarr datasets. Prior to this session, validation datasets were drawn from the same pool as training datasets using a ratio-based split (--val_split_ratio). Two improvements were requested:

  1. Dedicated validation folder: When a validation/ subfolder exists inside --data_folder, use those datasets exclusively for validation (with fallback to the original split-based approach when absent). The training folder should still be pruned; the validation subfolder should never be pruned.
  2. Per-component loss reporting: Compute and print MSE, PMSE, MAE/L1, and LPIPS individually at the end of each epoch for both train and validation, and append a summary row to a shared CSV every 5 epochs at a fixed path so all runs contribute to the same file.

A follow-up adjustment scaled the LPIPS metric by 1.5× to align its magnitude with the other loss components.

What Was Done

1. Dedicated validation/ subfolder support

At startup, the code detects whether {data_folder}/validation/ exists. When present, training discovery runs on the parent folder (excluding the validation subtree), and validation discovery runs on the subfolder. At each epoch rescan, only the training folder is pruned using split_target_train as the keep-count. The validation subfolder is never pruned. The ratio-based split fallback is fully preserved when no validation subfolder exists.

Bug fixed: The initial implementation accidentally placed the pruning call inside the else branch, meaning pruning was silently skipped when a validation subfolder was active. The fix moves _prune_oldest_to_target into the use_separate_validation_folder branch operating on the filtered discovered_train list.

3. train_epoch() updated

Added reporting_lpips parameter and component_totals accumulator updated inside torch.no_grad() after each batch. return_details=True now includes mse, pmse, mae, lpips keys. Both the single-pass and multi-chunk code paths accumulate and weight-average component metrics correctly.

4. validate() updated

Added return_details and reporting_lpips parameters. Returns a dict with loss, mse, pmse, mae, lpips when return_details=True. Empty-loaders early-return also returns the full dict with nan values.

5. _run_validation_dataset() updated

Added metric_updater: Callable[[Tensor, Tensor], None] | None parameter, called after each forward pass (outside the criterion) to capture per-component stats without affecting the training loss.

6. LPIPS 1.5× scaling

LPIPSLoss gained a scale: float = 1.5 parameter (default). forward() returns dist.mean() * self.scale. Applies to both training backprop (when mc_lpips_weight > 0) and reporting metrics.

7. CSV logging

Columns: date, time, tensorboard folder, epoch, unet_levels, hidden_dims, kernel_schedule, model parameter count (millions, 2 d.p.), mse_weight, pmse_weight, mae_weight, lpips_weight, train/val mse/pmse/mae/LPIPS.

  • Cadence: every 5 epochs
  • Header written only on first creation; subsequent runs append safely

At the end of every epoch, two new lines are printed:
